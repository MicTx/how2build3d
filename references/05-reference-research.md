# R0 · 参考研究与要素规划（场景构建的强制前置）

> 本文是 skill 的第 R0 阶段：**任何"真实地点/真实风貌"场景，先做参考研究，
> 再做数字构建。没有真实图像时，必须先产出完整的环境要素规划，再开工。**
> 方法论增强（2026-11-16）：吸收 Holodeck / SceneCraft / three-geo / BlenderGIS
> 的参考获取实践，新增查询派生、覆盖矩阵、参考对拍与归档许可四节；
> 调研依据见 `.distill/audits/2026-11-16_peer-reference-acquisition-study.md`。

## 多参考渠道（至少三源，每源独立记录）

| 渠道 | 拿什么 | 典型来源 | 产出 |
| --- | --- | --- | --- |
| 权威文本（百科/政府/设计院/通稿） | 硬数据：高度/面积/层数/年代/设计师/布局关系 | 官方百科与官网、政府公开数据、设计院与施工方通稿、权威媒体报道 | 事实清单（每条带出处 URL） |
| 权威地理数据（DEM/卫星/OSM） | 真实地形高程、建筑轮廓与层数、岸线与路网 | OSM 建筑轮廓与 `building:levels`/`height` 属性、SRTM/ASTER DEM、Google Earth（含历史影像时间轴）、卫星影像 | 地形剖面、平面轮廓、高度校验值（数字优先于目测） |
| 图像（街景/图库/游记/卫星图/实拍） | 体量比例、立面节奏、材质、色彩、天际线 | 街景（Google/百度/Mapillary）、CC 图库（Unsplash/Pexels/Flickr/Wikimedia Commons）、游记相册、实拍照片 | 逐图分解（每图 ≥5 条观察） |
| 视频/游记 | 动态：人流、声音、昼夜差异、招牌与灯光 | 游记视频、无人机航拍、纪录片、直播回放 | 动态要素清单 |
| 图纸/测绘（如有） | 平面关系、尺寸链 | 建筑图纸、测绘报告、总平面图 | 平面布局草图 |

**纪律**：三源互相矛盾时，以"官方文本/地理数据 > 图纸 > 图像 > 游记"排序；每条事实标注来源与置信度。图像渠道不可用时，文本先行并**显式列出待补图像清单**（不要假装研究过）。

## 查询派生（把"要素"翻译成能命中的查询）

参考图不是搜一次就有——检索质量取决于查询怎么写。规则：

1. **属性句优先于关键词**（来自 Holodeck 的描述式检索）：用
   `[地点/类型] + [要素名词] + [状态形容词] + [时间/天气]` 的属性句检索，
   例如"雨夜渔港"不要搜 `渔港`，要搜 `wet cobblestone harbor night rain reflective`——
   属性句命中的图自带你要的观感条件，省掉二次筛选。
2. **双语反查专业词**：中文概念先翻成该领域的英文行话再检索——骑楼→`arcade shophouse`、
   山墙→`gable wall`、干挂石材→`rainscreen stone facade`。行话命中的是业内图源
   （建筑摄影/材料商样图），直译命中的多是游客照。
3. **每类要素 ≥2 个查询变体**：换形容词（weathered/rusted/mossy）、换视角词
   （aerial/street level/close-up）、换时刻词（golden hour/blue hour）。
   一轮检索后若某要素命中率低，先改查询再下结论"找不到参考"。
4. **负向过滤**：图库检索加排除词（`-watermark -stock-illustration`），
   插画与 3D 渲染图不能当材质参考（它们本身就是"二手转述"）。

## 覆盖矩阵（参考图的最低配额）

"找到图"不等于"找够图"。单尺度参考（全是远景照）是细节断想的主要根因——
材质、密度、五金全都看不到。按下面矩阵核对配额，未满配额的格子列入待补清单：

| 维度 | 拿什么 | 数量下限（每个高权重要素） |
| --- | --- | --- |
| 远景 Establishing | 天际线、体量关系、整体色温 | 2 张 |
| 中景 Mid | 立面节奏、街具密度、人流与动线 | 3 张 |
| 特写 Close-up | 材质磨损、取色、五金与接缝细节 | 3 张 |
| 俯视 Aerial | 平面布局、路网、屋顶色（场景级，非逐要素） | 1 张 |
| 夜景 Night | 灯光位置、色温、辉光与招牌密度 | 2 张（含夜间场景必备） |
| 湿天 Wet | 反射行为、水洼分布、湿润色偏 | 1 张（雨/水场景必备） |

配额是下限不是目标：高权重要素（进 GAP 表前三大）的特写图优先补齐。
矩阵核对结果写进 R0 产出（每格：已满足 / 待补 + 查询派生改写记录）。

## 逐参考分解模板

```markdown
### 参考 #N（来源 URL / 图名，许可：__）
- 硬数据：高度 __m、层数 __、面积 __、朝向 __
- 体量关系：主体/裙楼/塔/附属的比例与相对位置
- 立面节奏：开窗尺寸与间距、材质分缝、装饰带位置
- 色彩：主体色 / 描边色 / 屋顶色 / 点缀色（取色，见下）
- 分层观察：前景 __ / 中景 __ / 背景 __（每层列 ≥3 件可见物）
- 密度计数：每米宽度 __ 个 __（灯柱/摊位/窗扇——数数，不猜）
- 尺度锚点：门高 __px = 2.1m（用图内已知尺寸物换算，禁止无锚点估比例）
- 取色记录：取色坐标 (x%,y%) → hex，每图 ≥5 个，注明光照条件
- 动态元素：人流密度、车辆、旗帜、灯串、昼夜差异
- 声音/气味（如有资料）：叫卖、音乐、食物
```

**深度要求**：分层观察防"只看主角"、密度计数与尺度锚点防"拍脑袋比例"、
取色带坐标防"凭印象配色"。三条都做不到的图，标注为"氛围参考"，
不得为硬数据 GAP 提供数值。

## 要素清单（16 类，无参考时的完整规划 scaffold）

没有真实图像时，R0 的产出不是"开写代码"，而是**对以下 16 类逐类给出决策**（每类：要素清单 → 视觉权重 → 是否入景 → 参数去向）。前 12 类是空间要素，后 4 类是**观感要素**——只做前者会得到「几何正确、质感塑料」的场景（见[观感转移审计](../.distill/audits/2026-11-14_quality-transfer-audit.md)）：

| # | 要素类 | 决策内容 |
| --- | --- | --- |
| 1 | 地形与水文 | 平地/坡地/水体；水位与岸线（真实地点优先查 DEM/OSM，不目测航拍） |
| 2 | 建筑主体 | 体量、层数、高度、平面关系（画平面草图） |
| 3 | 标志物 | 塔/碑/雕塑：高度、比例、与主体的构图关系 |
| 4 | 立面系统 | 开窗节奏、拱/券类型、材质分缝、装饰带 |
| 5 | 材质与色彩 | 主体色/描边色/屋顶色/地面色（取色表，带参考图坐标） |
| 6 | 街具与摊位 | 摊位、座椅、灯柱、遮阳、栏杆的密度与布局 |
| 7 | 人流与交通 | 人流密度、动线、车行边界 |
| 8 | 植被 | 树种、密度、季节状态 |
| 9 | 光照与天气 | 纬度→太阳高度、典型天气、昼夜 |
| 10 | 天际线与远景 | 远山/城市轮廓/天空特征 |
| 11 | 文化符号 | 文字/纹样/旗帜/招牌（语言与字体） |
| 12 | 声音 | 环境音、音乐、叫卖（进音频规格表或明确不做） |
| 13 | 光照情绪 | 时刻（黄昏/正午/夜）、对比基调、主光色温、辉光/体积光强度 → 映射光照分层与 shafts 参数 |
| 14 | 反射与湿润 | 干/湿/积水、反射面类型（水洼/玻璃/金属）、反射清晰度 → 映射 ssr-wet / 平面反射 / 环境强度 |
| 15 | 后处理风格 | 影调（胶片/数码/游戏）、对比/饱和/颗粒、镜头效应 → 映射 post-chain 校准表 |
| 16 | 材质磨损层级 | 每类表面的磨损程度与脏污分布（新/旧/废弃）、边缘磨损逻辑 → 映射 SL 材质目录与 macro 参数 |

**检查点**：16 类全部有决策（含"明确不做"也是决策）后才允许进入 S1。gap 表格式见下。

## GAP 表模板（R0 产出 → 场景验收标准）

```markdown
| 要素 | 真实参考值 | 当前场景值 | GAP | 修正动作 | 参数去向 |
| --- | --- | --- | --- | --- | --- |
| 标志物高度 | 真实值（来源） | 规划值 | 比例 | 修正动作 | 对应字段 |
| 观感：湿地反射 | 参考图水洼有锐镜面 + 湿沥青纵向拉伸 | 规划：无反射 | 资产层缺失 | 接入 ssr-wet + 平面反射 | `uRefl*` / quality.planar |
```

每条 GAP 都要有"参数去向"——落到哪个常量文件哪个字段。**观感 GAP 还要有"资产映射"**——落到 `assets/` 的哪个系统或 references/07 的哪个最小实现。R0 的验收 = gap 表全部有去向，最大的三条 GAP 已排进本次构建，且至少一条观感 GAP 有资产映射。

## 参考对拍（构建后闭环：渲染图 vs 参考图）

R0 不是"一次前置"——SceneCraft 的核心循环是**渲染图像交回视觉模型评审、迭代
refinement**。本仓库的落点：构建出第一版后，把真实参考图当"对照组"做同机位对拍：

1. **选锚定参考**：从覆盖矩阵里挑 1–3 张（建议 1 张俯视 + 1 张主视平视 + 1 张夜景/湿天）。
2. **对齐机位**：用九展厅与 `__setShot` 把渲染相机调到与参考图同视角（高度/朝向/焦段近似），时刻与天气对齐（黄昏场景就调黄昏光照，雨天就开 rain）。本仓库的样本场景把「云甲板朝向、太阳烧穿云隙、远云融进地平线」写进了天空 shader 注释——这就是「时刻与天气对齐」的可执行参照 [src:L4230-L4251]。
3. **截图并排**：渲染截图（`evidence/frames/`）与参考图并排放进验收记录，各按逐参考分解模板审一遍。
4. **登记 delta**：每组对拍产出 ≥3 条 delta 观察（"参考里檐口有滴水线、场景没有"），逐条进 GAP 表（参数去向 + 资产映射），排进下一轮迭代。
5. **对拍是正常迭代步骤**：视觉感知门禁过（不塑料）≠ 与真实参考一致（不跑偏）；两者都要。

## 参考归档与许可

- **观察入仓、图像外链**：仓库只存 manifest（下表），版权图像以 URL 引用，
  不打包进仓库（`assets/` 零外部资产门禁管运行时；这条管研究资料的红线）。
  自己拍摄的实拍照片不入库——公开快照红线同样适用（人脸/车牌等个人信息先裁剪或打码，原图留本地）。
- manifest 落 `evidence/references/manifest.md`（evidence 内 manifest 可 track，图片本身不可）：

```markdown
| # | 要素类 | 来源 URL | 许可 | 尺度/时刻/天气 | 观察条数 | 进 GAP 编号 |
| --- | --- | --- | --- | --- | --- | --- |
| R1 | 建筑主体 | https://… | CC BY-SA 4.0 | 中景/昼/干 | 7 | G1,G3 |
```

- 许可不明 → 只做观察记录，不复制分发；图库 ToS 禁止转存的一律只留链接。

## 反模式

1. **拍脑袋高度**：不做 R0，凭感觉定标志物高度（硬数据偏差可达 50% 以上）。
2. **单参考**：只看一张图，把游记视角当全部事实。
3. **假图像研究**：说"参考了图片"但拿不出逐图分解。
4. **要素沉默**：16 类里有一类没有决策记录（沉默 ≠ 决策）。
5. **只做几何保真**：把体量/比例修到像素级，却从未做观感 GAP——交付「几何正确、材质塑料」的场景。
6. **单尺度参考**：参考全是远景照，材质/密度/五金全靠猜——先查覆盖矩阵，再改写查询补特写图。
7. **只存链接不存观察**：manifest 一堆 URL、零条分解——链接不是研究，逐图分解才是。
8. **无许可打包**：把图库版权图 commit 进仓库或发布快照——观察入仓、图像外链。

## 执行节奏（把 R0 排进 spec）

R0 本身就是 spec 包的前置任务，建议拆成三步：

1. **收集**：多渠道检索 + 查询派生，产出参考清单并核对覆盖矩阵配额——本步的 verify 是"清单存在且 ≥3 源，矩阵每格已满足或列入待补"。
2. **分解**：逐参考按模板分解 + 16 类要素决策——本步的 verify 是"16 类无沉默项"。
3. **GAP 表**：真实值 vs 规划值逐条对齐，参数去向落到 `world.mjs` 的具体字段——本步的 verify 是"三大 GAP 有去向且已排进本次构建"。

与 spec 的衔接：R0 的三步对应三个任务卡；GAP 表作为 S0/S3/S4 等下游任务的**输入引用**（gap 编号 `G1..Gn` 可被后续任务的 verify 断言引用，例如 `grep -q "G1" world.mjs`）。构建后的**参考对拍**是第四张任务卡（S9 之后执行，verify = ≥3 条 delta 已进 GAP 表）。

**对虚构场景同样适用**：世界观设定就是你的"参考源"——把设定文档当权威文本走同样的分解流程；没有设定文档就先写设定（16 类清单的决策记录本身就是设定文档）。

**价值分布**：硬数据（高度/面积/层数）> 关系网（布局/相对位置）> 色彩 > 图案。配色可以靠通识蒙对，硬数据必须查（地理数据源优先于航拍目测）。
