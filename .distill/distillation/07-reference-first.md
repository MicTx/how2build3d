## 为什么这一步不可跳

1. **硬数据无法脑补**：塔高 70m vs 33.9m、建筑面积 9 万 m²、步行街 775m"T"字型——这些
   只有权威文本能给。脑补版本会在"构图正确"的幻觉里失真一倍。
2. **关系网无法脑补**：真实布局是关系图（清真寺在塔东北侧、1/2 号楼构成内向庭院、
   3/4 号楼与广场的关系）——单看照片推不出全貌。
3. **12 类要素是完备性检查**：无参考（虚构场景）时，"沉默的要素类"就是漏掉的系统。
   逐类决策强制把植被/人流/声音/文化符号这些"想不到的"变成显式决策。

## v3 增补：参考图采集与细节挖掘（2026-11-16）

R0 的"收集"步骤此前只有"≥3 参考源"这一个门槛——它保证了有研究，但不保证**研究够深**：
单尺度参考（全是远景照）同样能过门槛，材质/密度/五金照样靠猜。v3 按四节增强
`references/05-reference-research.md`（依据见 `.distill/audits/2026-11-16_peer-reference-acquisition-study.md`）：

1. **查询派生**：属性句优先于关键词（Holodeck 的描述式检索）、双语行话反查、每要素 ≥2 查询变体、负向过滤——把"找不到参考"降级为"查询没写对"。
2. **覆盖矩阵**：远景/中景/特写/俯视/夜景/湿天六维配额，未满列待补清单——"找够图"有了可核对的判据。
3. **深度分解**：逐图模板加分层观察（前/中/背景）、密度计数、尺度锚点（门高=2.1m）、取色坐标——比例与色彩从"凭印象"变"可复现"。
4. **参考对拍闭环**：构建后同机位渲染 vs 参考图并排审 delta，回灌 GAP 表（SceneCraft 的渲染-评审循环）——R0 从一次前置升级为闭环。

门禁同步：`docs.manifest.json` 的 05 条目把「查询派生 / 覆盖矩阵 / 参考对拍 / 归档与许可」列入必备小节，缺节判红。
