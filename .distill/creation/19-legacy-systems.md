# 创物 · 上游遗留四系统

> 这四套系统从未进入 18 族资产清单：海鸥群藏在背景模块里，菜单/开场/过场/结算与玩法状态机缠在 L6202 巨行，评分公式只出现在结算回调的一行三元表达式里。它们不是“没价值”，而是“没有独立 kit，也没有独立对账行”。本篇按系统拆出法则、链路与决策，最后给出移植切入点。

## 海鸥群（ambient flock）

### 法则（带引用）

**法则 1 · 一只鸟 = 6 个顶点 + 2 个 vec4 实例属性**：每只海鸥只有两片三角翼（6 顶点），轨道中心与半径进 `aOrbit`，相位、角速度、扑翼频率、翼侧标志进 `aPar`；没有骨骼、没有贴图、没有逐鸟 draw call [src:pretty:L44164-L44200]。

**法则 2 · 飞行动画全部在顶点着色器里算**：轨道角 `ga = phase + uTime·speed`；机头方向取轨道切线 `(-sin, 0, cos)·sign(speed)`；扑翼用 `smoothstep` 在滑翔与振翅之间插值，翼尖按 `|z|` 抬升、翼展按 `|flap|` 压缩；身体再叠两个不同频率的上下浮动 [src:pretty:L18627-L18651]。

**法则 3 · 远景观感优先于物理正确**：材质是无光照近黑剪影，关闭雾、关闭投影、关闭视锥剔除；整群合并成一个 mesh，名字固定 `gulls`，缓存键 `saltline-gulls` [src:pretty:L18627-L18651]。海鸥不需要被照亮，它只需要在天空里“像一群鸟”。

**法则 4 · 一只时钟驱动整片背景**：背景更新只把 `uTime.value += dt`，海鸥、灯牌闪烁、吊机、船体共享同一个 uniform 时钟；海鸥本身不维护位置状态 [src:pretty:L44260-L44297]。

### 思维链

**约束**（事实）：单文件、零贴图、零骨骼；海鸥只是氛围，不值得一套动画系统 [src:pretty:L18627-L18651]。
**目标**（事实）：远处有持续运动的小剪影，不抢戏、不掉帧。
**候选**（推断）：A billboard 精灵；B 带骨骼的低模；C 6 顶点网格 + 顶点着色器程序化飞行。
**选择**（事实）：C。顶点数比精灵还少，运动完全由公式决定，CPU 每帧只写一个 uniform。
**兜底**（事实）：整群合并、关闭视锥剔除与阴影，避免“单 mesh 包围盒在原点导致整群被裁”的经典错误。
**推断边界**：作者是否先试过 billboard 无法证实；但从“两片三角翼 + 翼侧标志位”的建模方式看，目标是可编程扑翼，而不是可朝向相机的贴片。

## 菜单与开场流

### 法则（带引用）

**法则 1 · 菜单是 JS 模板字符串，不是 HTML 文件**：`pM(i,e)` 一次性构建 `.menu` 根节点与全部屏幕（title/paused/dead/complete）以及设置面板，插进 `#ui`；屏切换只改 `data-screen` 与 `.open` 类 [src:L6110-L6112] [src:pretty:L58403-L58440]。单文件约束下，UI 与游戏共享同一份生命周期。

**法则 2 · 四屏 + 一面板，语义先于样式**：标题屏给“开始/设置/介绍/操作”，暂停屏给“继续/设置/操作/重开”，死亡屏给“生存时间 + 已切断中继”，简报屏给“用时/命中率/摧毁数/重试/评级”；设置面板是 `role="dialog" aria-modal`，三个 tab 用 `aria-selected`，开关用 `aria-pressed` [src:L6114-L6132] [src:L6134-L6144] [src:L6146-L6151] [src:L6153-L6164] [src:L6166-L6199]。

**法则 3 · 菜单不懂游戏，只发命令**：按钮统一走 `data-act`，点击时先发 `ui:click`，再查 `e[act]` 回调表；deploy/resume/restart/retry/redeploy 全部由游戏侧实现 [src:pretty:L58733-L58763]。菜单不读生命值、不判断输赢。

**法则 4 · 开场是“可跳过的时间轴”，不是第二套状态机**：标题态由 `z(dt)` 驱动相机巡航；按开始后进入 `intro`，3.5 秒（重试 1.3 秒）内依次做淡入淡出、地点卡、无线电、HUD 显影，时间到直接 `T()` 进 playing；skipIntro 则一步到位 [src:pretty:L59214-L59222]。

**法则 5 · 设置是版本化 schema，读写都失败安全**：`saltline.settings.v1` 默认 `{quality:"auto",sens:1,invertY:false,volume:.8,fov:74}`；读取逐字段白名单 + clamp，写入 try/catch；只有用户操作才落盘 [src:pretty:L58356-L58382] [src:L6087-L6087]。

### 思维链

**约束**（事实）：单 HTML、零 UI 框架、要同时支持键鼠/触屏/手柄与中英混排 [src:L6088-L6112]。
**目标**（事实）：一个可键盘导航、可读屏、可触屏的完整菜单，且不增加构建步骤。
**候选**（推断）：A 静态 HTML 写死四屏；B JS 模板字符串 + 事件委托；C 引入前端框架。
**选择**（事实）：B。模板字符串与游戏代码同文件，屏切换只是 dataset 与类名，无虚拟 DOM。
**兜底**（事实）：面板手动做焦点陷阱（Tab 在首尾按钮间循环）、Esc 关闭、显示后聚焦主按钮；Pointer Lock 不可用时降级为拖动视角并给出提示。
**推断边界**：无障碍属性是作者主动加的，但没有自动化读屏测试；可访问性程度只能按代码判断，不能按实测声明。

## 过场相机与 debugCut

### 法则（带引用）

**法则 1 · 过场不是视频，是 十二 个 pos/look 关键帧**：关卡数据给出 十二 个 `{pos, look}`（从闸口 -34,1.6,6.2 一路推到泊位 二十八点四,1.9,十七点二），相机与视点各自成为一条样条 [src:pretty:L21333-L21357]。

**法则 2 · 插值是逐轴 Catmull-Rom，不是线性 lerp**：给定全局进度 `V∈[0,1]`，先映射到段号与局部 `t`，取前后各一点做三次 Hermite 基函数；四个控制点保证过关键帧且切线连续 [src:pretty:L58823-L58847]。

**法则 3 · 标题相机是“样条 + 呼吸 + 淡入淡出”的合成**：总时长 `max(26, 路径长/1.15)` 秒；进度做 0.75 线性 + 0.25 smoothstep 的偏置；位置叠 0.05/0.035/0.05 的三轴正弦，视点叠 0.2/0.12，滚转叠 0.006；首尾 1.8s/1.6s 淡入淡出 [src:pretty:L58823-L58847]。手写关键帧给出构图，噪声给出“手持感”。

**法则 4 · debugCut 是可寻址的测试面，不是作弊键**：`debugCut()` 找到第一个未切断的中继，直接调用正常切断函数 `me(P)`，跳过战斗与移动；它不改状态机、不跳关卡，只把“任务终点”提前 [src:pretty:L58800-L58812] [src:pretty:L51928-L51952]。

**法则 5 · bench 复用同一条路径**：性能模式以 30 秒周期在相邻关键帧间做 smoothstep 巡航，2 秒预热后每秒打印 avg/median/p99 与错误数 [src:pretty:L59521-L59545]。测试相机与标题相机共享数据，不共享插值器（bench 用线性段间插值，标题用 Catmull-Rom）。

### 完整链路

| 阶段 | 做法 | 常量 | 证据 |
| --- | --- | --- | --- |
| 关键帧 | 关卡 `cinematicPath` 12 点 | 起点 (-34,1.6,6.2)、终点 (28.4,1.9,17.2) | [src:pretty:L21333-L21357] |
| 预处理 | 转 Vector3，统计总长 `E.len`，不足两点用起终点兜底 | 最小长度 4 | [src:pretty:L58823-L58847] |
| 标题巡航 | `t += dt`，到时长归零；进度偏置后采样 pos/look | 时长 `max(26, len/1.15)`、FOV 50 | [src:pretty:L58823-L58847] |
| 开场 | intro 状态只做淡入/地点卡/无线电/HUD 显影 | 3.5s / 重试 1.3s | [src:pretty:L59214-L59222] |
| 测试跳转 | `debugCut()` → 首个未切断中继 → `me()` | 无 | [src:pretty:L58800-L58812] |
| 性能巡航 | bench 30s 周期、2s 预热、每秒采样 | p99/errors/GPU | [src:pretty:L59521-L59545] |

### 思维链

**约束**（事实）：没有视频文件、没有时间轴编辑器；过场只需把玩家从闸口带到泊位 [src:pretty:L21333-L21357]。
**目标**（事实）：一条能反复播放、可被测试跳过的相机路径。
**候选**（推断）：A 每个镜头硬编码位置/朝向；B 关键帧 + Catmull-Rom；C 物理相机碰撞路径。
**选择**（事实）：B。关键帧由关卡作者摆位，插值器只负责平滑；相机与视点分离，构图可独立调。
**兜底**（事实）：路径少于两点时用玩家起点与前方 8 米生成两段；bench 模式用同一路径的线性段间插值，避免依赖标题态。
**推断边界**：12 点是作者手摆的，无法证明经过样条优化；但 `E.len` 参与时长计算，说明“匀速感”是刻意处理的。

## 简报与结算屏

### 法则（带引用）

**法则 1 · 结算不是总分，是三个可解释维度**：时间（<270s 得 2，<400s 得 1）、命中率（≥0.5 得 2，≥0.3 得 1）、零重试（+1），合计 0–5，映射六档评语“险象环生/火力全开/稳扎稳打/干净利落/精准果断/完美突击” [src:pretty:L59195-L59210]。每个加分项都能对玩家解释。

**法则 2 · 结算数据来自战斗统计，不来自 UI**：`combat.stats` 提供 shots/hits/kills，`run.time` 提供用时，`retries` 提供重试；命中率为 `hits/shots`，无射击时为 null，UI 显示“—” [src:pretty:L59195-L59210]。

**法则 3 · 死亡与完成是两种结算，不共用文案**：死亡屏只给“生存时间 + 已切断中继”，完成屏给“用时/命中率/摧毁机械/重试次数/评级”；两者分别由 `setDead` 与 `setDebrief` 填 [src:L6146-L6151] [src:L6153-L6164] [src:pretty:L58680-L58700]。

**法则 4 · 结算屏有延迟，让镜头先说话**：死亡态 1.5 秒后才显示死亡屏，完成态 3.3 秒后才显示简报；期间饱和度、淡出继续动画 [src:pretty:L59240-L59252]。结算不是弹窗，是镜头的落点。

| --- | --- | --- | --- |
| 触发 | 撤离点命中 → `ee()`；玩家死亡 → `setDead` | — | [src:pretty:L59195-L59210] |
| 冻结 | 无敌、禁用玩家、退出指针锁、隐藏 HUD/提示 | — | [src:pretty:L59195-L59205] |
| 统计 | shots/hits/kills + time + retries | — | [src:pretty:L59195-L59210] |

### 思维链

**约束**（事实）：结算必须在一屏内解释清楚，且不能引入服务端或排行榜 [src:L6153-L6164]。
**目标**（事实）：让玩家知道“快不快、准不准、稳不稳”。
**候选**（推断）：A 加权连续总分；B 三个离散维度相加；C 只给时间排名。
**选择**（事实）：B。三个维度各自有阈值，最高 5 分，六档文案；任何一项都能单独解释。
**兜底**（事实）：零射击时命中率为 null，显示“—”，不按 0% 惩罚；重试次数只影响最后一分。
**推断边界**：阈值 270/400 秒与 0.5/0.3 命中率是作者按关卡长度调的，不是通用标准；移植时应重标定，而不是照抄。

## 迁移法则

这四套系统目前**没有独立 kit、没有 element-manifest 行、没有专属展厅**。若要移植，切入点如下：

- **海鸥群**：并入背景/氛围资产（`assets/backdrop-kit` 或 `fx-kit` 的 ambient 子模块）。API 建议 `createGullFlock({ count=12, seed=5521, color, radius })`，内部保持“单 mesh + 两属性 + 顶点着色器 + 一个 uTime”，并暴露 `update(dt)` 与 `stats()`。验收放在 `backdrop` 厅：同一机位拍“有鸟/无鸟”两张，断言 draw call 不增加、鸟群不被视锥裁掉。
- **菜单与开场流**：从 `hud-kit` 分出一个 `ui-kit`（菜单屏 + 设置面板 + 焦点管理），`hud-kit` 只管战斗内 HUD。保留 `saltline.settings.v1` 的键名与 clamp 规则；把 `data-act` 命令表作为 UI 与游戏的唯一边界。验收用 DOM 快照 + 键盘 Tab 循环 + 设置往返。
- **过场相机与 debugCut**：抽成 `camera-path` 工具：`sampleCatmullRom(points, t, outPos, outLook)` 与 `durationFor(path, speed)`；标题相机、bench、未来过场共用。`debugCut()` 作为测试钩子保留在 game 对象上，但必须是“调用正常任务函数”，不能直接改状态。验收：同 seed 下相机轨迹采样逐点一致。
- **简报与结算屏**：评分抽成纯函数 `rateRun({time, accuracy, retries}) -> {score, label}` 放进 `combat-kit`，DOM 填屏留在 `ui-kit`。这样评分可单测、可重标定，不依赖菜单模块。验收：给定三组边界输入（270/400s、0.5/0.3、0/1 重试）输出稳定。
- **对账与证据**：若提升为一等族，在 `harness/element-manifest.json` 增加 `gulls/menu/cutscene/briefing` 四条（或折叠进 `backdrop/hud/loop` 并写明理由）；每族至少一个可进入的检视面——海鸥进 `backdrop` 厅、菜单进 `render` 厅、过场用 `?cam=` + `__setShot` 采样、结算用脚本强制 `debugCut` 后截图。否则这批系统会继续处于“代码里有、账本上没有”的灰区。
