# 创物 · 特效（fx）

> 上游锚点：`sources/jimao-3a-game/index.html` L5939（Ev billboard 构建器、双池、弹着分发；按 prettify 偏移展开） ｜ 我方资产：`assets/fx-kit.mjs`（`FX_POOL_SPEC` lit 1400 / add 3040 + 四环形池 + 24 发射器，`FX_DRAW_CALLS=5`） ｜ 对账：`harness/element-manifest.json` fx 族 ｜ 验收：`node harness/gates/complete.mjs --scene examples/parity`

## 构建法则

**法则 1 · 两个池、两种光的语言，共享一个顶点着色器**：烟/尘/火核走 lit 池（alpha 混合、参与太阳与半球环境光），火花/闪光/曳光走 add 池（加法混合、不受光）；两者用同一个 `Ev` 构建器、同一套 `aPos/aAxis/aCol/aMisc` 属性与同一份顶点着色器，只有片元与混合状态不同 [src:pretty:L46329-L46368]、[src:pretty:L46281-L46327]。断言：新增一种效果时先选“它属于哪种光”，而不是新建一个材质。

**法则 2 · billboard 有三种朝向模式，由 `aMisc.y` 分派**：0 = 面向相机（烟团、闪光），1 = 沿速度轴拉伸（曳光、雨丝、火花条），2 = 贴合表面法线（冲击环、贴花）；拉伸模式还会把屏幕宽度下限钳到 `dist*uPx*1.4`，避免远处曳光细到消失 [src:pretty:L46230-L46246]。这条不变式让一个 instanced mesh 同时承担“点状、线状、面状”三类粒子。

**法则 3 · 粒子是 SoA 池，热循环零分配**：每个池用约 三十 条并列数组（px/py/pz、vx/vy/vz、age/life、drag/grav/wind/turb、frame/mode/flags/ramp…）加一个 free-list 索引栈，`emit` 只写数组并返回槽位，`update` 只做数值推进 [src:pretty:L46451-L46526]。断言：FX 的帧成本与粒子数线性相关，但不产生 GC 峰值；池满时 `emit` 返回 −1，调用方必须容忍这种“效果被丢弃”。

**法则 4 · 弹着特效按表面分发，没有一个通用爆炸**：`impact` 的 switch 按 metal / wood / water / rubber / dirt / glass / enemy 分支：金属出两段火花 + 环形冲击 + 瞬时点光 + 金属贴花；木出木屑与尘；水直接调水花；玻璃出高亮碎片与裂纹贴花；敌人出定向血雾 [src:pretty:L47650-L47857]。断言：表面语义是特效的第一参数，未知表面必须落到 concrete 兜底，而不是“什么都不发生”。

**法则 5 · 水面命中复用雨溅射的水冠，不另造一套**：`case "water"` 只调 `T(L, 1)`，而 `T` 正是雨溅射的水冠发射器——5 片环、2 片雾滴、14 颗弹起水珠，最后再补一圈扩散环 [src:pretty:L47692-L47695]、[src:pretty:L47547-L47630]；片元是同一段 crown 冠形 [src:L5813-L5824]。这条法则消灭了“雨水花与子弹水花长得不一样”的分裂感。

**法则 6 · 贴花是图集格 + 环形池，不是独立 mesh**：8 格 4×2 图集（金属×2 / 混凝土×2 / 木 / 烧灼 / 烟熏 / 玻璃）由 `da` 表按 surface 取格 [src:pretty:L45812-L45812]；decal 池 160 槽环形复用，根组只挂 decal/debris/shell/lit/add 五个 mesh [src:pretty:L47274-L47279]。断言：弹孔、烧痕、玻璃裂纹全部共享一个 draw call 与一套深度测试。

## 思维链

### 决策链一 · 11 种效果怎么塞进 5 个 draw call

**约束**（事实）：单文件、前向渲染、后处理只有一条全屏 pass；FX 与场景共享同一个深度缓冲。
**目标**（事实）：枪口焰、曳光、弹着、爆炸、烟、尘、壳、碎片、贴花都要能同帧出现。
**候选**（推断）：A 每种效果一个 mesh/材质，11 种以上材质意味着十几次状态切换；B CPU 点精灵逐帧上传顶点，粒子一多就卡在总线；C 两个 GPU billboard 池 + 图集分格 + 四个小环形池。
**选择**（事实）：C。lit/add 各一个 InstancedBufferGeometry，图集用 aMisc.x 选格，tracer/debris/shell/decal 各自独立环形池但共享根组 [src:pretty:L47260-L47279]。
**兜底**（事实）：`push` 在容量耗尽时返回 false，`emit` 返回 −1；特效是“可丢弃”的，不允许为了播放一个火花而扩容或阻塞 [src:pretty:L46408-L46431]。

### 决策链二 · 火与烟为什么必须分成两种混合

**约束**（事实）：火焰是发光体，烟是遮光体；两者经常重叠，且都要被场景几何正确遮挡。
**目标**（事实）：火能烧穿烟、烟能挡住火的后层，重叠处不能出现“加法把烟洗白”。
**候选**（推断）：A 全部加法，简单但烟会变成发光雾；B 全部 alpha，火会失去 HDR 亮度；C 双池 + lit 池内的自发光分支。
**选择**（事实）：C。lit 片元用 `aMisc.w ≥ 2` 标记“自发光火舌”，走 `core = t.b*t.b` 的 alpha 混合火核，烟仍按太阳/环境光着色 [src:pretty:L46299-L46311]；add 池只承载火花、闪光、曳光 [src:pretty:L46317-L46327]。
**兜底**（事实）：lit 片元最后做 premultiply `rgb *= a`，保证与后处理 AgX 的混合约定一致；软粒子用深度纹理在近交处淡出，避免烟团切进地面 [src:pretty:L46272-L46279]、[src:pretty:L46315-L46315]。

### 决策链三 · 弹着信息如何从物理变成可读的材质反应

**约束**（事实）：物理只给 `point/normal/surface/dir`，没有材质实例；同一发子弹可能打在金属、木箱、水洼、玻璃或敌人身上。
**目标**（事实）：每种表面都要有“这是什么材质”的一眼可读反应，且贴花要留在正确朝向。
**候选**（推断）：A 每个表面写独立函数并从调用方分派，逻辑散落；B 统一函数内 switch，把参数表集中；C 只做贴花，不做粒子。
**选择**（事实）：B。`C(point, normal, surface, dir, enemy)` 内 switch，每个分支自己组合火花/碎屑/水花/贴花 [src:pretty:L47632-L47857]；法线向上且落在积水上的命中还会被改判为 water [src:pretty:L47641-L47644]。
**兜底**（事实）：未知 surface 默认 concrete；贴花按 `da` 表取格，表外回退 `bullet_concrete`；敌人命中强制 `surface="enemy"`，不参与积水改判 [src:pretty:L47641-L47644]。

**推断边界**：候选集与作者排除理由为反推；池容量、图集布局、混合开关、软粒子公式、各 surface 的粒子数与颜色均可逐行核对。需要特别说明：上游 FX 全部压在一个 118 KB 的压缩行里，本文件用 `[src:pretty:L…]` 指向 prettify 后的可读行；这些行号与压缩源码的对应关系由 `evidence/frames/app.pretty.js` 固化，不构成对作者意图的额外声明。

## 迁移法则

**资产路由**：fx 族唯一入口 `assets/fx-kit.mjs`。`createFxKit(THREE, opts)` 的参数全部注入（rng/physics/ground/events/lightPool/wind/sunDir/camera），kit 内不顶层 import three、零 `Math.random`；无 three 时纯 CPU 池仍可推进，供 node 自测。接场景时先 `root` 挂组，再按事件接线：`weapon-kit.muzzleWorld → muzzleFlash/tracer`、`combat/impact → impact`、`player:step|land → splash`。

**参数重绑点**：

| 参数 | 重绑到 | 注意 |
| --- | --- | --- |
| `rng` | 场景定种 rng | 图集另用独立定种 PRNG（默认 9173），保证逐次构建一致 |
| `physics.raycast` | 物理 kit | 用于遮挡判定（近墙火花减半）与爆炸地面高度；缺省时返回安全默认 |
| `ground.isPuddle` | 地面族查询 | 水花/积水改判依赖它；缺省时按非水处理 |
| `sunDir/sun/sunLo/sunHi/ambLo/ambHi` | 天空与光照 | lit 池的受光参数，必须与主光同源 |
| `camera` | 主相机 | 软粒子深度与 `uPx` 每帧从相机/渲染目标更新 |
| `atlas` | 图集覆盖 | `FX_ATLAS` 的 4×2 布局是 shader 的 `uAtlas` 约定，改布局要同步所有 frame 索引 |
| `wind` | 天气向量 | 烟/尘的漂移方向，建议与 weather-kit 的风一致 |

**对账行**：`harness/element-manifest.json` fx 族（`asset: assets/fx-kit.mjs`，floors `fxKinds ≥ 5`、`fxPools ≥ 2`，upstream refs `[src:pretty:L48488-L48510]`、`[src:pretty:L45423-L45485]`）；`examples/parity/scene.elements.json` fx 条目（`fxKinds=11 / fxPools=2 / drawCalls=5`）；资产门禁 marker `createFxKit / FX_POOL_SPEC / FX_KINDS / FX_ATLAS`。三者同时成立，才允许声称“FX 池整套接线”。
